# ຕັ້ງຖານຂໍ້ມູນອອນລາຍ (Supabase) — ໃຫ້ພະນັກງານໃຊ້ມືຖືຂອງຕົນເອງ

ເຮັດຄັ້ງດຽວ ໂດຍຜູ້ດູແລລະບົບ (ເຈົ້າ). ໃຊ້ແຜນຟຣີໄດ້.

## 1. ສ້າງໂປຣເຈັກ
1. ເຂົ້າ https://supabase.com → Sign in (ໃຊ້ GitHub ໄດ້) → **New project**.
2. ຕັ້ງຊື່ (ເຊັ່ນ `st-hr`), ຕັ້ງ Database Password (ເກັບໄວ້), Region ເລືອກ **Southeast Asia (Singapore)**. ກົດ Create ແລ້ວລໍ ~2 ນາທີ.

## 2. ປິດການຢືນຢັນອີເມວ (ສຳຄັນ)
**Authentication → Sign In / Providers → Email**: ປິດ **Confirm email** ແລ້ວ Save.
(ບັນຊີພະນັກງານເປັນ `ST-012@c-xxxx.sthr.app` ທີ່ບໍ່ມີອີເມວຈິງ ຈຶ່ງຢືນຢັນທາງອີເມວບໍ່ໄດ້.)

## 3. ໃສ່ໂຄງສ້າງຖານຂໍ້ມູນ
**SQL Editor → New query** → ເປີດໄຟລ໌ `supabase/schema.sql` ໃນ GitHub (ປຸ່ມ Raw) → ຄັດລອກທັງໝົດວາງ → **Run**. ຕ້ອງຂຶ້ນ "Success". ແລ່ນຊ້ຳໄດ້ ບໍ່ເປັນຫຍັງ.

## 4. ຕັ້ງ "ລະຫັດສ້າງບໍລິສັດ"
ໃນ SQL Editor ແລ່ນ (ປ່ຽນ `ລະຫັດລັບຂອງເຈົ້າ` ເປັນຂອງເຈົ້າເອງ):
```sql
insert into public.platform (key, value) values ('signup_code', 'ລະຫັດລັບຂອງເຈົ້າ')
on conflict (key) do update set value = excluded.value;
```
ຄົນທີ່ຈະສ້າງບໍລິສັດໃໝ່ຕ້ອງໃສ່ລະຫັດນີ້ — ຄົນແປກໜ້າທີ່ມີ key ສ້າງບໍລິສັດບໍ່ໄດ້.

## 5. ເອົາ 2 ຄ່າ ມາໃຫ້ແອັບ
**Project Settings → API**:
- **Project URL** (ເຊັ່ນ `https://abcdxyz.supabase.co`)
- **anon public** key

> ❌ ຫ້າມເອົາ **service_role** key ໄປໃສ່ໃນແອັບ ຫຼື ສົ່ງໃຫ້ໃຜ — ມັນຂ້າມລະບົບຄວາມປອດໄພທັງໝົດ. 2 ຄ່າຂ້າງເທິງ (URL + anon) ເປີດເຜີຍໄດ້ ເພາະຄວາມປອດໄພຢູ່ທີ່ກົດຂອງຖານຂໍ້ມູນ (RLS).

## 6. ໃຊ້ງານ
1. ເປີດ https://taosivi.github.io/st-hr/ → **🌐 ເຂົ້າບໍລິສັດອອນລາຍ** → ໃສ່ URL + anon key → ແຖບ **ສ້າງບໍລິສັດໃໝ່** → ໃສ່ລະຫັດສ້າງບໍລິສັດ, ຊື່ບໍລິສັດ, ຊື່ເຈົ້າຂອງ, PIN 6 ຕົວ. ເຈົ້າຂອງເຂົ້າດ້ວຍລະຫັດ `ST-001` + PIN.
2. ເພີ່ມພະນັກງານ (ນຳເຂົ້າ Excel) → **ສິດ & ການອະນຸມັດ** → **ອອກ PIN ໃຫ້ຄົນທີ່ຍັງບໍ່ມີ** (ສ້າງບັນຊີ + PIN ຊົ່ວຄາວ 6 ຕົວ ໃຫ້ແຕ່ລະຄົນ).
3. ໃນໜ້າດຽວກັນ ມີ **ລິ້ງຕັ້ງຄ່າມືຖືພະນັກງານ** — ສົ່ງລິ້ງ + PIN ຊົ່ວຄາວ ໃຫ້ແຕ່ລະຄົນ. ເຂົາເປີດລິ້ງໃນມືຖື → ເຂົ້າດ້ວຍລະຫັດພະນັກງານ + PIN → ຕັ້ງ PIN ຂອງຕົນເອງ.

## ຄວາມປອດໄພ — ສິ່ງທີ່ຖານຂໍ້ມູນບັງຄັບເອງ
- ແຕ່ລະບໍລິສັດເຫັນຂໍ້ມູນຂອງຕົນເອງເທົ່ານັ້ນ.
- ບົດບາດ (ເຈົ້າຂອງ / ຫົວໜ້າ / ບັນຊີ / ຜູ້ກວດສອບ) ປ່ຽນໄດ້ສະເພາະເຈົ້າຂອງ — ພະນັກງານຍົກສິດໃຫ້ຕົນເອງບໍ່ໄດ້.
- **ເງິນເດືອນ, ເລກບັນຊີ, ເບ້ຍລ້ຽງ**: ເຫັນໄດ້ສະເພາະ ເຈົ້າຂອງ, ບັນຊີ, ຜູ້ກວດສອບ ແລະ ຕົວເອງ. ຫົວໜ້າ ແລະ ເພື່ອນບໍ່ເຫັນ.
- **ໃບໜ້າ (face template)**: ເຫັນສະເພາະເຈົ້າຂອງໃບໜ້າ (ຄົນອື່ນເຫັນແຕ່ຈຳນວນທ່າ).
- **ສະລິບເງິນເດືອນ**: ແຕ່ລະຄົນເຫັນສະເພາະຂອງຕົນເອງ.
- ຫົວໜ້າເຫັນການລົງເວລາ/ລາ/ຄຳຂໍ ສະເພາະພະແນກທີ່ດູແລ.
- ການແຈ້ງເຕືອນ: ເຫັນສະເພາະຂອງຕົນເອງ.
- Audit log: ເພີ່ມໄດ້ ແຕ່ແກ້/ລຶບບໍ່ໄດ້ — ເຈົ້າຂອງ ແລະ ຜູ້ກວດສອບເບິ່ງໄດ້.
- PIN ເກັບໃນລະບົບ Auth ຂອງ Supabase (hash) — ບໍ່ຢູ່ໃນຂໍ້ມູນບໍລິສັດ.

## ຂໍ້ຈຳກັດທີ່ຕ້ອງຮູ້ (ຍັງບໍ່ເຮັດ)
- **ກົດເນື້ອໃນ** (ເຊັ່ນ ພະນັກງານແກ້ສະຖານະການສະແກນຂອງຕົນເອງເປັນ "ອະນຸມັດ") ແອັບເປັນຜູ້ກວດ ບໍ່ແມ່ນຖານຂໍ້ມູນ. ຄົນທີ່ຮູ້ເລື່ອງເຕັກນິກ ແລະ ມີບັນຊີ ອາດໂກງຂໍ້ມູນຂອງຕົນເອງໄດ້. ຖານຂໍ້ມູນກັນການເບິ່ງຂໍ້ມູນຄົນອື່ນ ແລະ ການຍົກສິດ ແຕ່ບໍ່ກັນການແກ້ຂໍ້ມູນຂອງຕົນເອງທັງໝົດ.
- PIN 6 ຕົວເລກ ຖືກລອງເດົາຜ່ານອິນເຕີເນັດໄດ້ (Supabase ຈຳກັດຈຳນວນຄັ້ງຕໍ່ IP). ຢ່າໃຊ້ PIN ທີ່ເດົາງ່າຍ.
- ຮູບສະແກນເກັບໃນແຖວການສະແກນ — ຖ້າມີການສະແກນຫຼາຍພັນເທື່ອ ການໂຫຼດຈະຊ້າລົງ (ຈະແຍກຮູບອອກໃນຮອບຕໍ່ໄປ).
- ເມື່ອພະນັກງານລາອອກ ແອັບປິດການເຂົ້າໃຊ້ຕາມວັນທີ່ສິ້ນສຸດ ແຕ່ບັນຊີເຂົ້າລະບົບຍັງຢູ່ໃນ Supabase (ລຶບໄດ້ດ້ວຍຟັງຊັນ `admin_remove_login` — ຍັງບໍ່ມີປຸ່ມ).
- ສະແກນຕອນບໍ່ມີອິນເຕີເນັດ: ເກັບໃນມືຖື ແລ້ວສົ່ງເມື່ອມີສັນຍານ. ກິດຈະກຳອື່ນ (ຂໍລາ, ອະນຸມັດ) ຕ້ອງມີອິນເຕີເນັດ.
- ຂໍ້ມູນໃໝ່ຈາກຄົນອື່ນຂຶ້ນພາຍໃນ ~20 ວິນາທີ (ຍັງບໍ່ແມ່ນ real-time).
